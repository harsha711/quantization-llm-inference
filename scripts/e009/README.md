# E009 cyclic compressed execution comparison

The predeclared E009 entry in docs/EXPERIMENTS.md defines the scope, memory design and5% two-series criterion. This harness imports E008 operand preparation and E004 timing/bridge calls. Corrected E006 A, existing GPU dequantization and cuBLAS code/binaries remain unchanged. All three paths use W_hat with FP16 inputs/output and FP32 compute. The private handle explicitly sets and checks cuBLAS math mode16.

All four representations stay alive across every path/count. Marlin uses its own packed/scales allocation, pre-materialized cuBLAS reads independent FP16 W_hat, and unfused dequantizes independent project-layout Q/S into one reusable guarded temporary before every GEMM. The temporary is overwritten in timed calls. Sequential stream ordering permits reuse. Output/Marlin workspace storage is separate per weight. The bridge's default cuBLAS workspace is library-managed with no exposed size, so reported tensor totals exclude it, runtime objects and graph/event storage. Extra live representations are not intentionally read by other timed paths. Byte counts are storage/access descriptions, not cache residency or traffic measurements.

On a freshly verified c10 interactive allocation, export absolute PROJECT_ROOT, SLURM_JOB_ID, SLURM_JOB_NODELIST=c10 and SLURM_NODELIST=c10. Run scripts/e009/prepare_arc.sh on c10. Inspect its logs and run the prerequisite-stage analyzer through prun. Only after that pass run validate_arc.sh, inspect full rectangular and unfiltered memcheck/racecheck/synccheck logs, then the validation-stage analyzer. Only after that pass run measure_arc.sh. Scripts use ARC prun, one rank/16 OpenMP threads, refuse raw-output overwrites and stop on failures. They preserve historical gates and leave the user allocation running. No unattended allocation or batch job is created.

The six shape/count cells rotate implementation order so every implementation occupies each position twice. Series2 is an independent process with shape/count traversal and each cell's implementation order reversed. Exactly36 rows use10 whole-cycle warmups/100 whole-cycle samples. No artificial flush or intermediate event is inserted. Device-required lock/scratch handling stays inside timing. Allocation, capture, reference and validation stay outside. Every row checks three direct cycles and three poisoned graph cycles, all active outputs, workspace/temporary guards and final unfused reconstruction. Each weight's individual GPU reconstruction is checked bitwise before composed paths. One reused temporary prevents observing intermediate reconstructions after a whole cycle, so intermediate correctness is also tested through every saved output and individual reconstruction checks. No validation copies are added to timed cycles.

Run `python3 scripts/e009/analyze.py RESULTS --stage prerequisite`, then `--stage validation`, then without stage for the complete evidence. Run `python3 scripts/e009/check_analysis.py RESULTS` and `python3 scripts/e009/analyze.py --self-test`. Analyzers check raw samples and derived statistics, exact row/order counts, operand identity against E008 and across methods/series, disjoint allocations, reconstruction/guard/FP64 checks, mode16, preserved manifests and measured tooling hashes. Negative checks mutate temporary evidence copies only.

Fresh speedup is comparator median divided by Marlin median. Marlin gain is100*(1-Marlin/comparator), meaningful only if>=5% in both series per shape/count/comparator. Amortized latency is cycle median divided by count, never separately sampled. Keep all outliers. Compressed versus pre-materialized execution includes different kernels and footprints. Versus unfused measures the implementation as a whole, not fusion alone. No inference/token-throughput, stable-tail or unique-bottleneck claim. No additional profiling or next experiment is authorized.
