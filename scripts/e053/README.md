# E053: two-row reuse in v3

One fixed candidate, `v3_m2`, shares each weight load/unpack across two rows while retaining v3's split rule and each row's arithmetic order. M1 and unsupported shapes use v3. No layout, quantization, pipeline, scale-hoisting or default change. See the predeclaration and attempt records in `docs/EXPERIMENTS.md`.

Primary: four-matrix E045 cycles, seeds 3–6, M4/M8 on 4096² and both 4096/11008 rectangles, 10 warmup/100 raw samples, two reversed series. Accept only with >=5% lower cycle median versus v3 in all 12 cells. M1/M2/M16, single-matrix read-flush/reused sweeps and tc_ladder/Marlin/cuBLAS comparisons remain separately labeled. cuBLAS cycle math mode is 16.

Stages are baseline prerequisite/profile, inspected candidate numerical/sanitizer validation, then dependent full timing/profile. Source payloads are embedded in batch scripts generated by `submit.sh` from committed HEAD. The absolute BeeGFS project root is exported at submission. Launch only with sbatch/prun after checking live allocation/GPU state. Never use historical job IDs as an allocation.

Offline inspection on retrieved evidence:

```bash
python3 -B scripts/e053/check_gate.py BASELINE --stage baseline
python3 -B scripts/e053/check_gate.py VALIDATION --stage validation --baseline BASELINE
python3 -B scripts/e053/analyze.py --self-test
python3 -B scripts/e053/analyze.py FULL
```

Verify `all.sha256` before adding derived analysis to a retrieved directory. Native benchmark/library/control SASS equality, every active output's FP64 check, candidate/parent bitwise equality, repeated and poisoned graph checks, output-tail guards and all three sanitizer tools precede timing. The original v3 check hides individual sanitizer stdout, so E053 additionally records raw parent/candidate sanitizer summaries. Kernel-replay durations and counters are not application latency. Scope is one GPU type, one node, synthetic weights, GEMM level only.
