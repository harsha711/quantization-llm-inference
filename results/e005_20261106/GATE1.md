# E005 Gate 1: source-derived bounds and progress argument

**Subsequent Gate 3 invalidation:** racecheck reports a temporal read/write hazard when B storage is reused for reduction, including in unchanged A and the official wheel. The spatial index/capacity argument below remains useful, but does not establish a safe phase transition. E005 stops before timing. No claim of sanitizer-clean execution or complete memory safety follows from these bounds.

## Shared accesses and enabled paths

Selected specialization is FP16 A/C/scales, uint4b8 B, group_blocks=8, thread_m_blocks=1, m_block_size_8=true, thread_n_blocks=thread_k_blocks=8, 256 threads, four stages. `marlin_template.h:312–340` disables zero points and the 8-bit activation scale prefix. Runtime bias, atomic reduction and global scale are disabled. FP32 global reduction is enabled. Per-column scaling and FP8/FP4 paths are not enabled.

Every pointer offset is measured in 16-byte `int4` units (`:506–551,698–716`). `a_sh_stride=16`, `a_sh_stage=128`, so each A stage is 2048 B and four stages use 8192 B. `b_sh_stride=64`, `b_sh_stage=512`, so each B stage is 8192 B and four use 32768 B. `s_tb_groups=1`, `s_sh_stride=s_sh_stage=16`, so each scale stage is 256 B and four use 1024 B. `zp_sh_stage=0`. The declared `sh_red_size=272` int4 is 4352 B and `sh_bias_size=16` int4 is 256 B. The overlay formula is max(32768,4352+256)=32768 B. Bias is disabled but its reserved subregion [4352,4608) remains in this overlay. No additional alignment padding is needed: every base/stage length is divisible by 16.

Output reshuffling (`:1425–1540`) writes individual halves with max index 1079 and reads int4 rows below the declared output-layout span. All remain in the overlay. `s_sh_rd=8*((threadIdx/32)%2)+(threadIdx%32)/4` is 0..15. B fetches/read fragments stay within 512 int4 per stage (`:758–788,838–845`). Other lane addresses are not consumed by this instruction. A global read predicates guard M tails (`:662–665`). Reading inactive A rows is inherited behavior and does not contribute to valid output rows.

Thus 41984 B covers all enabled accesses, including the scratch accesses that exceed the nominal reduction-buffer formula. The unmodified host estimate assumes 16 A rows and returns 50176 B. It is not applied to M=16 or to another selected tile/type.

## Locks, scratch and partitioning

`marlin_template.h:342–500` divides flattened (column tile,K tile) work into strips of length `iters=ceil(k_tiles*part2_mn_tiles/grid)`. Full part1 tiles have one owner and no global reduction. Every part2 column segment is assigned slice_idx 0..slice_count-1, in reverse CTA order. `locks_off` is either the column-strip index when part2 tiles < grid, or the boundary CTA index otherwise. Only a split column accesses it. It is nonnegative and < grid for these cases. `safety.py` reproduces the formulas, verifies contiguous slice indices, exact K coverage, lock bounds and every dependency edge for the initial five validation K/N pairs (later extended with candidate smoke K=256,N=2048) and both grids. The rectangular C case exercises the second indexing branch and reaches lock 70. The old upstream check `workspace.numel()>=sms` alone is insufficient. The E005 caller allocates and verifies 4*sms lock entries for every configuration, with guards. This allocation is intentionally identical across A/B/C.

Each FP32 scratch slot has c_size=16*128*4/16=512 int4=8192 B (`:1379–1390`). The 64 active threads access indices `locks_off*512+64*j+t` with even j=0,2,4,6 and t=0..63, giving per-slot offsets [0,64),[128,192),[256,320),[384,448). Highest exclusive relative byte is 7168. Original small-M allocation (`marlin.cu:589–598`) is sms*16*256 floats = 2*sms slots of 8192 B. Hence every slot <2*sms fits without expanding upstream C_tmp. Exact maximum exclusive accessed bytes on the 36-SM device are 261120 square (both grids), 113664/580608 for K4096,N11008 A/C, and 261120 for K11008,N4096. Capacity is 589824 B. Common guards surround the allocation. Capacity arithmetic is complemented by explicit index/coverage enumeration.

Doubling grid changes stripe length, participating CTAs per column, part1/part2 split, and number/order of FP32 partial reductions. In the first rectangle, A has 72 complete part1 tiles plus 14 part2 tiles, while C has all 86 columns in part2 and 68 split columns. C is not a pure occupancy change and output bits need not match A.

## Reset, synchronization and progress

Locks are zeroed once before ordered calls. `barrier_acquire` (`:151–165`) uses a GPU acquire load of slice_idx, followed by a block barrier. `barrier_release` (`:168–185`) joins writers, fences GPU memory, and increments the counter. Last owner resets it to zero. `global_reduce_fp32(first,last)` skips reading uninitialized scratch in the first owner, initializes every fragment later owners read, and skips the final scratch write. Scratch therefore requires allocation but no per-call clearing. At kernel completion every used lock is zero. Ordered same-stream calls and graph replay wait for preceding kernel completion. No overlapping calls share workspace. Initial lock clearing, scratch poisoning and allocation are outside timing. No required per-call maintenance is omitted. Tests check counters and guards after direct/replayed calls and poison outputs outside capture before each replay.

For every split column, slice_idx=0 belongs to its largest CTA index and waits for zero, so it has no predecessor. Higher slice_idx waits on a strictly larger CTA index. The finite model asserts all these edges. Across a CTA's subsequent column visits, work advances in column order. Reused boundary locks are reset by the last owner before the next segment uses them. This gives an acyclic dependency direction and no circular lock ownership. Source-level reasoning is needed because tools do not prove inter-block forward progress.

Before a candidate launch, query the actual compiled kernel with cudaFuncGetAttributes and cudaOccupancyMaxActiveBlocksPerMultiprocessor, using its actual launch shared size. Require at least two blocks/SM and launch no more than 2*sms CTAs. A's sms-CTA launch similarly fits its reported maximum. This avoids deliberately oversubscribing the resource-resident grid with spinning CTAs. On ordinary CUDA scheduling, ready predecessors can be admitted because the complete launch fits the resource capacity. CUDA does not guarantee a particular CTA scheduling order or achieved concurrent residency. The argument is bounded to this device/kernel, acyclic waits and queried capacity, not a portable proof of every future scheduler or a claim that 72 CTAs run concurrently. Timeouts and repeated executions complement this argument without replacing it.

Unsupported dispatch, including M=16/64, leaves original kernel/grid/shared allocation unchanged. Query/trace those fallbacks and compare their strict numerical errors and repeated timings. The C ABI exposes only the fixed dense FP16/G128 contract and validates positive/divisible shapes. Python owns the typed contiguous tensors and checks common workspace capacities. It is an experiment harness, not a public general-purpose Marlin API.

## Gate 3 outcome and limits of the initial argument

`sanitizer_racecheck.log` reports reads at template line 843 against writes at line 1237. The initial overlay derivation verified disjoint live-size bounds but assumed phase ordering. Source `:1659–1674` has a per-thread `cp_async_wait<0>()` followed by `thread_block_reduce()`, without a block-wide entry barrier before the first overlay writes at `:1237`. A per-thread async wait does not itself join the other warps' ordinary shared loads. This is consistent with the report. The pipelined final prefetch may be unused when a stripe ends, so an output-affecting race has not been isolated. This is not grounds to dismiss the report or claim a tool false positive. Numerical agreement does not establish race freedom.

The bounded main-shape diagnosis reproduces two reported errors in unchanged local A and two in the isolated official wheel, with exit 99 for each. The wheel lacks source line information, so mapping its reported instruction offsets to exactly the same source pair remains unverified. Its matching dense specialization and inherited report do not establish a newly introduced reservation/grid bug. No body barrier, compiler workaround, suppression or replacement optimization was attempted. Performance/held-out/profiler gates remain unreleased. Revisit requires a separately authorized safety resolution or documented applicable tool explanation, then complete revalidation of a newly matched control/candidate build.
