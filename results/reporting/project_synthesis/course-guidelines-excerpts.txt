           Baseline First, Then Profile

              WOR KF LOW

              3. Parallelize / optimize that spot.
              4. Re-measure; verify results still correct.
              5. Sweep threads / cores / problem size.

           Never optimize before you have measured. The profiler, not intuition, tells you where the time

           Common Pitfalls to Avoid

              NO BASELINE
              Speedup is meaningless without a correct, timed serial reference.

              WR ON G AN SWER S, FAST
              Always verify the parallel output matches the baseline.

              SI NG LE DATA POIN T
              One thread count tells you nothing — sweep p and problem size.

              OV ER� SCOPING
              Too ambitious → no results. Narrow it so you can finish and measure.

              O PTI MI Z ING B LIND
              Tuning before profiling wastes effort on cold code.

              L ATE START
              Leaving experiments to the last week leaves no room to debug.
