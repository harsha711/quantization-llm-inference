## E006 exact ordering and targeted upstream context

- [PTX async-group wait](https://docs.nvidia.com/cuda/parallel-thread-execution/#data-movement-and-conversion-instructions-cp-async-wait-group) documents executing-thread group completion and excludes ordering guarantees for other memory operations. [CTA barriers](https://docs.nvidia.com/cuda/parallel-thread-execution/#parallel-synchronization-and-communication-instructions-bar) order ordinary prior reads/writes across participants. These apply directly to E006's source `cp_async_wait<0>()` followed by the added `__syncthreads()`. Draining each thread and then joining the block closes the specific B-to-reduction lifetime gap. A spatial shared bound or a warp-only ldmatrix join cannot provide this dependency.
- [Compute Sanitizer report modes](https://docs.nvidia.com/compute-sanitizer/ComputeSanitizer/index.html#racecheck-report-modes) distinguish byte hazards from grouped analysis. The square detailed run's100 displayed entries and 29698 errors cannot be compared directly with two grouped control errors. Installed2026.3.0.0 build38855100 is captured in E006 metadata. [Release notes](https://docs.nvidia.com/compute-sanitizer/ReleaseNotes/index.html) contain mbarrier, bulk-copy and warp-sync fixes, but no exact applicable limitation was established for the observed unsynchronized ordinary cross-warp LDS/STS accesses. No reports were suppressed.
- [vLLM issue 11205](https://github.com/vllm-project/vllm/issues/11205), older v0.6.4 development source/A10G, was resolved by [PR 11493](https://github.com/vllm-project/vllm/pull/11493/files), merge [5dba2575065f5e27d468f2776e3d460a21d916e6](https://github.com/vllm-project/vllm/commit/5dba2575065f5e27d468f2776e3d460a21d916e6) on2025-01-02. - [PR 16850/template introduction](https://github.com/vllm-project/vllm/commit/1d0c9d6b2d74e6884c6c63f4856ac0a2cddd0508), commit 1d0c9d6b2d74e6884c6c63f4856ac0a2cddd0508 on2025-05-05, again aliases B and reduction storage and contains the drain/reduction transition. Later W4A8 commit 1656ad37045579999a5a9ef3b940f945cd92bb4e changes the base to sh_new. Pinned v0.33.0 retains the alias and lacks this entry join. E006 preserves the targeted patches/blame. This is provenance, not a claim to have searched all upstream history or established when incorrect output began.
- [Original Marlin issue 42](https://github.com/IST-DASLab/marlin/issues/42),2025-07-24, concerns per-column async scales/A100, disabled in our G128 path. ## E007 terminal-load scope and measurement

- E006's [source and compiled dataflow analysis](../results/e006_20261106/ACCESS_ANALYSIS.md) identifies the terminal unused B lookahead for the specific small-M specialization. E007 additionally inspects the A fragment's identical alternating-buffer index. This supports a bounded candidate, not a measured shared-load bottleneck. The finite stripe-tag model is supplementary evidence and full matched-output checks remain required.
- [PTX ldmatrix](https://docs.nvidia.com/cuda/parallel-thread-execution/#warp-level-matrix-instructions-ldmatrix) requires the specified collective participation. E007's new runtime predicate derives only from CTA-uniform K-stripe counters and compile-time subfragment position. It therefore skips or executes each A matrix load uniformly across its warp. It changes no barrier participation or async group, and preserves the [CTA barrier](https://docs.nvidia.com/cuda/parallel-thread-execution/#parallel-synchronization-and-communication-instructions-bar) added in E006.
- E007 preserves the actual metric query before profiling. `smsp__inst_executed_op_ldsm.sum` measures executed LDSM warp instructions. `smsp__inst_executed_op_shared_ld.sum` and its `pred_on_any` counterpart distinguish issued LDS warp instructions from those with at least one participating thread. These are not predicated integer thread-instruction counts and must not be summed as FLOPs. An initially considered thread-level shared-load metric name was absent from the saved target query and was replaced before any profile launch. There was no unsupported-metric GPU run.
- Source/build/SASS manifests and raw records are separate in `results/e007_20261106/`. All 16 corrected-control device functions must match E006. Exactly the intended specialization may change in the candidate. The official wheel is used for lossless repacking only and supplies no performance denominator. No dependency upgrade or generalized hardware assumption is introduced.
- E007's completed profiles use 7 replay passes per body. [Nsight source metrics](https://docs.nvidia.com/nsight-compute/ProfilingGuide/index.html#source-metrics) distinguish predicate-inclusive warp instructions from participating thread instructions. Here predicate-inclusive LDS/LDSM issue counts stay equal, `pred_on_any` LDS falls 1.931%, and total warp instructions rise 1.757%. The exact SASS shows four new conditional LDS/LDSM pairs. Static counts must include predicates and scalar `LDS` without dot modifiers. Both bodies have 121 static LDS/LDSM opcodes, including 70 permanently false sites, leaving 51 potentially active sites. Initial summaries/snapshots remain preserved and corrected counts are independently checked. No application latency benefit is inferred from the slightly shorter replay duration.
