## Repository evidence

- [CONTRACT.md](CONTRACT.md), `src/quant.cpp`, and `src/cuda/w4a16_naive.cu` define this project's symmetric offset-coded INT4 quantization and required FP16 reconstruction. This is the project's chosen contract, not a claimed standard packed LLM format.
- `results/baseline_meta.txt`, `results/baseline_c7.csv`, `results/baseline_c7.log`, and `results/ncu/summary.txt` document historical c7 evidence. Binary provenance and cache interpretation have the limits recorded in H001–H003 of [EXPERIMENTS.md](EXPERIMENTS.md).
- Final E001 evidence is `results/inblock_c58_20261106_final/`, source checkpoint `2b7d4fc`, evidence checkpoint `0d8fec0`. `analyze.py` checks the 48-row series and generates `speedups.csv`/`profile_summary.csv`. `verify_sass.py` checks exact aligned device-code parity. Raw profiles, commands, metadata, hashes, and control evidence remain alongside these summaries.
- E002 evidence is `results/e002_c58_20261106/`, source checkpoint `91bd042`, criteria checkpoint `dc37ec6`, evidence checkpoint `c7ea4b4`. `analyze.py` checks all 56 rows, full-output E001/E002 bitwise comparisons, six sanitizer runs, and declared criteria. `verify_sass.py` checks saved/rebuilt E001 and E002-tail SASS parity. Static opcode counts and dynamic Nsight executed-instruction counters are separate evidence. No new hardware assumption is introduced.
- E003 evidence is `results/e003_c58_20261106/`, implementation `5a7bcaf`, measurement-script/source checkpoint `25b2291`, criteria `53bb695`, evidence `a16cbc5`. `analyze.py` validates 90 final rows, twenty full-output comparisons against E002, six sanitizer summaries, twenty exact selector/shape profiles, source hashes, and a same-binary repeated timing series. `verify_sass.py` compares naive/E002 instruction/control encodings while normalizing build-specific anonymous namespace symbols. `resource_usage.txt` reports all eight E003 specializations with zero stack/local allocation. The first complete event series and interrupted profiler attempt remain in `results/e003_c58_20261106_attempt1/`. M-row reuse is now measured, while its component effects remain coupled.
- Runtime `cudaDeviceProp.l2CacheSize` and historical Nsight `device__attribute_l2_cache_size` both reported 32 MiB. Use new runtime/metadata evidence for new GPU claims rather than transferring an unrelated accelerator's specifications.

No external INT4 implementation was benchmarked in E001–E003. E004 adds pinned vLLM Marlin as a separate Tensor Core comparator with a lossless adapter. Its measured performance is not a contribution or speedup of the retained scalar kernels. Further project optimizations remain separately authorized experiments.

Pinned released [vLLM v0.33.0 source](https://github.com/vllm-project/vllm/tree/4ba787ec9959e566d3b587a796dff 07673324da5), Apache-2.0, including Marlin's Elias Frantar copyright and Neural Magic modifications. Initial main `4d82b56913be009d97c59fb13e471bde14948e1f` was inspected but is not the selected comparator. The release tag peels to `4ba787ec9959e566d3b587a796dff07673324da5`, matching the official wheel's embedded version commit. Release selection avoids compiling/patching the entire serving framework. The inspected source subset and license are preserved in E004 evidence.

- [Kernel tests](https://github.com/vllm-project/vllm/blob/4ba787ec9959e566d3b587a796dff 07673324da5/tests/kernels/quantization/test_marlin_gemm.py) are the direct-operator entry point. Select GPTQ `uint4b8`, group_blocks=8, FP16, FP32 global reduction. Their looser aggregate test tolerance does not replace this project's strict elementwise FP64 threshold.
- [Packing helpers](https://github.com/vllm-project/vllm/blob/4ba787ec9959e566d3b587a796dff 07673324da5/vllm/model_executor/layers/quantization/utils/marlin_utils_test.py) supply the weight permutation, and [Marlin utilities](https://github.com/vllm-project/vllm/blob/4ba787ec9959e566d3b587a796dff 07673324da5/vllm/model_executor/layers/quantization/utils/marlin_utils.py) supply grouped scale permutation and lock sizing. - [Dequantization](https://github.com/vllm-project/vllm/blob/4ba787ec9959e566d3b587a796dff 07673324da5/csrc/quantization/marlin/dequant.h), [kernel template](https://github.com/vllm-project/vllm/blob/4ba787ec9959e566d3b587a796dff 07673324da5/csrc/quantization/marlin/marlin_template.h), and [MMA instructions](https://github.com/vllm-project/vllm/blob/4ba787ec9959e566d3b587a796dff 07673324da5/csrc/quantization/marlin/marlin_mma.h) establish decode, FP16 scaling and FP32 accumulation/reduction choices. - [Dispatcher](https://github.com/vllm-project/vllm/blob/4ba787ec9959e566d3b587a796dff 07673324da5/csrc/quantization/marlin/marlin.cu) defines shape checks, automatic tile selection, workspace and internal scratch allocations. Its ordered configurations are existing standard tuning, not a novel project mechanism. [CMake architecture selection](https://github.com/vllm-project/vllm/blob/4ba787ec9959e566d3b587a796dff 07673324da5/CMakeLists.txt) includes forward-compatible Marlin targets. Actual wheel coverage and selected execution must still be checked on sm_120.

- [cuBLAS 13.0 numerical behavior and math modes](https://docs.nvidia.com/cuda/archive/13.0.3/cublas/index.html#cublasmath-t) documents `CUBLAS_MATH_DISALLOW_REDUCED_PRECISION_REDUCTION`, which forces mixed-precision reductions to use compute precision rather than output precision. E004 uses this flag after a reproducible strict-tolerance failure of the default mode. Passing with the flag is configuration evidence, not an inspection of cuBLAS's proprietary reduction internals.

## E005 safety and matched-build evidence

- [CUDA Runtime occupancy APIs](https://docs.nvidia.com/cuda/cuda-runtime-api/group__CUDART__OCCUPANCY.html) define `cudaOccupancyMaxActiveBlocksPerMultiprocessor` for an actual function, block size and dynamic shared allocation. E005 queries the compiled sm_120 kernel. The result is a maximum resource capacity, not evidence that two CTAs ran concurrently. `attributes.log` is target evidence.
- [PTX ldmatrix](https://docs.nvidia.com/cuda/parallel-thread-execution/#warp-level-matrix-instructions-ldmatrix) specifies which lanes supply row addresses. The x2 eight-row path consumes addresses from lanes 0–15. E005's finite A-stage bound applies to those supplying lanes. This source instruction rule corrected an initially overbroad address model.
- [Compute Sanitizer shared-memory race checking](https://docs.nvidia.com/compute-sanitizer/ComputeSanitizer/index.html#racecheck-tool) covers shared-memory hazards and supported asynchronous-copy synchronization. It does not justify treating an unchanged control's report as harmless or prove inter-block progress. Installed 2026.3.0 reports are preserved. [Release notes](https://docs.nvidia.com/compute-sanitizer/ReleaseNotes/index.html) were checked, but no applicable documented false-positive explanation was established for this report.
- Pinned template `marlin_template.h:843,1203–1254,1659–1674` supplies the B-load/reduction overlay and its phase transition. E005's spatial proof passed but racecheck reported a temporal hazard between line 843 and 1237. A per-thread `cp.async.wait_group` does not replace a block-wide join of ordinary shared loads. The final prefetch may be unused at stripe termination, so output relevance remains unisolated. Source inspection supports an explanation to investigate, not a proven new upstream bug or an accepted workaround.
- The wheel reproduces a racecheck report on the same dense specialization in a separate process without libe005.so. Its lack of line metadata prevents an exact source-offset equivalence claim. E005 therefore records an inherited report and stops before performance. E004’s earlier successful numerical/performance record remains historical and is not retroactively a sanitizer-clean external-kernel claim.
- `results/e005_20261106/pinned-source.tar.gz` preserves all original device headers, host dispatcher, helper subset, license and the two added compile headers from exact release source. `e005-host.patch` records only host-state/accounting/launch diagnostics. One binary and one device entrypoint serve A/B/C. Local 126 registers versus wheel 122 are a provenance difference. SASS/resources/source hashes and loaded paths are preserved. No candidate-only compiler flag or device-body change was made.
